# Governança de Dados

A evolução tecnológica, especialmente o barateamento do processamento e armazenamento, tornou os dados um recurso valioso. Isso impulsionou a adoção de **Decisões Orientadas por Dados (Data Driven Decisions)**, onde as informações são usadas para guiar estratégias de marketing, investimentos e aquisições.

No entanto, a eficácia dessas decisões depende diretamente da qualidade dos dados. Dados incompletos ou imprecisos podem levar a conclusões errôneas e, consequentemente, a más decisões.

**Exemplo**: Uma ação promocional baseada em dados de vendas incompletos de uma loja (devido a problemas de sistema) pode direcionar recursos para o local errado, ignorando o verdadeiro desempenho das outras unidades.

### Governança de Dados: Definição e Propósito

A governança de dados é a solução para garantir a integridade e o valor dos dados. Ela é a **soma de processos, princípios e decisões** que visam:

- Garantir valor e eficiência no uso dos dados de uma organização.
- Considerar todas as partes interessadas, incluindo a própria organização, stakeholders e a sociedade.
- Assegurar a privacidade, qualidade, disponibilidade e segurança dos dados.

## DAMA e a Roda de Disciplinas da Governança de Dados

A governança de dados integra boas práticas de diversas áreas relacionadas a dados. Para entender quais são essas áreas, é fundamental conhecer a DAMA.

### A DAMA (Data Management Association)

A DAMA é uma referência teórica e a responsável por um dos principais frameworks de governança de dados do mercado. Conhecê-la é essencial para:

- Obter uma base teórica sólida.
- Compreender os termos-chave da governança de dados.
- Comunicar-se eficazmente com outros profissionais da área.

### Disciplinas da Governança de Dados segundo a DAMA

A DAMA propõe uma "roda de disciplinas" que são parte integrante da governança de dados. São elas:

- Arquitetura de dados
- Modelagem de dados
- Operação e armazenamento
- Segurança de dados
- Integração e interoperabilidade
- Gestão de documentos e conteúdo
- Dados de referência e dados mestres
- Business Intelligence e Data Warehousing
- Metadados
- Qualidade de dados

É importante notar que um profissional de governança de dados não precisa ser especialista em todas essas áreas, mas deve entender como elas se interligam e contribuem para o objetivo principal da organização: extrair valor com eficiência dos dados.

## Benefícios da Governança de Dados

A governança de dados atua como um guia para as decisões de uma organização relacionadas aos dados. Apesar do custo de operacionalizar suas diversas disciplinas, cada vez mais empresas estão investindo nela devido a quatro motivos principais:

- Conformidade
- Eficiência
- Decisões orientadas por dados (Data-driven decisions)
- Monetização

### Conformidade: O Primeiro Grande Motivador

A conformidade é o principal impulsionador para o investimento em governança de dados. Nos últimos anos, houve um aumento significativo na criação de regulamentações, tanto em nível internacional quanto nacional, que estabelecem as regras para o uso de dados pelas organizações.

Essas regulamentações focam especificamente em dados pessoais. Exemplos no Brasil incluem a LGPD (Lei Geral de Proteção de Dados) e o Marco Civil da Internet. Para as empresas, estar em conformidade com essas legislações é essencial, garantindo que as leis específicas sobre dados sejam respeitadas.

### Eficiência
---

- **Redução de Retrabalho**: A governança de dados minimiza a necessidade de refazer tarefas em todas as etapas do ciclo de vida dos dados. Isso significa menos tempo e recursos gastos corrigindo erros ou coletando informações novamente.
- **Extração de Valor com Menos Recursos**: Com dados bem governados, é possível obter insights e tomar decisões estratégicas de forma mais econômica, utilizando menos recursos para alcançar os objetivos.

#### Como a Governança de Dados Promove a Eficiência?

- **Qualidade de Dados**: Uma das disciplinas da governança de dados é a qualidade. Ela garante que os dados sejam precisos, completos e confiáveis.
    - **Exemplo Prático**: Imagine uma equipe de marketing que precisa escolher uma loja para uma promoção. Ao analisar os dados de vendas, percebe-se que a loja campeã está com vendas muito baixas. Sem a governança, a equipe poderia tomar uma decisão errada.
        - **Problema**: Dados incorretos (sistema fora do ar, vendas não computadas).
        - **Consequência sem Governança**: Retrabalho para coletar dados novamente, refazer relatórios, perda de vantagem competitiva por decisões baseadas em informações erradas.
        - **Solução com Governança**: Implementar verificações de qualidade de dados. Isso assegura que os dados reflitam a realidade, evitando relatórios errados e retrabalho.

**Objetivo Central**: A governança de dados busca a eficiência em todos os processos que envolvem dados, desde a coleta até a tomada de decisão.

### Data Driven Decisions (Decisões Orientadas por Dados)
---

- **Modelo de tomada de decisão** que se baseia em dados para refletir a realidade da empresa.
- Contrapõe-se ao **modelo antigo, baseado na intuição**.
- Decisões baseadas na realidade tendem a ser mais acertadas a longo prazo.

#### Exemplo Prático

- Aplicativos de streaming recomendam séries e filmes baseados no histórico de consumo do usuário (ex: se você gosta de romances, verá mais romances).

#### O Problema dos Dados que Não Refletem a Realidade

- Se os dados usados para a decisão não correspondem à realidade (ex: sua mãe usa seu perfil de streaming e as recomendações mudam para o gosto dela), a premissa das Data Driven Decisions falha.
- As decisões baseadas nesses dados incorretos não serão boas.

#### A Importância da Qualidade dos Dados

- É crucial garantir a qualidade, integridade e veracidade dos dados antes de tomar qualquer decisão.
- Isso assegura que a decisão não seja apenas "baseada em dados", mas sim uma "boa decisão baseada em dados".

#### Conclusão e Governança de Dados

- Garantir que os dados sejam íntegros, de qualidade e verídicos é o terceiro grande motivo pelo qual as empresas investem em governança de dados.
- Isso garante a tomada de boas decisões orientadas a dados.

### Monetização
---

A monetização é o quarto e um dos mais importantes motivos para as empresas investirem em governança de dados, frequentemente sendo o objetivo final. Ela pode ocorrer de duas formas principais:

1. **Criação de Produtos de Dados**: Empresas podem desenvolver produtos ou serviços que extraem valor dos dados que já possuem. Isso significa transformar os dados brutos em algo útil e vendável.

2. **Venda de Dados**: Outra forma é vender os dados acumulados ao longo do tempo para outras empresas.

#### Exemplo Prático

Imagine uma vendedora de polpas de frutas da Paraíba querendo expandir para Santa Catarina.

- Sem dados sobre as vendas na nova região, ela poderia comprar informações de vendas do último ano de uma empresa do Paraná.
- Esses dados revelariam os sabores mais populares e as tendências de vendas por estação (inverno/verão), auxiliando no gerenciamento de estoque.

**Bureaus de Dados**: Existem empresas especializadas, chamadas **Bureaus de dados**, que coletam, cultivam e vendem dados sobre clientes ou produtos.
- Embora a venda de dados possa ter uma conotação negativa devido a escândalos passados, como o da Cambridge Analytica, ela também pode ser muito positiva.
- **Exemplo Positivo**: Uma empresa nova no setor de crédito, sem muita experiência em prevenção à lavagem de dinheiro, pode comprar informações relevantes de um Bureau de dados para se proteger.

## Governança: alinhando negócios e tecnologia

A governança de dados se manifesta em diferentes níveis hierárquicos:

**Nível Estratégico**: Envolve um comitê de diretores e especialistas, com a figura central do **Chief Data Officer (CDO)**, que guia as estratégias de dados.

**Nível Tático**: Representado pelo Data Governance Office, que define políticas e procedimentos. Aqui atuam profissionais como analistas de governança de dados e equipes de privacidade, conformidade, modelagem e arquitetura.

**Nível Operacional**: Todas as pessoas que interagem com dados têm responsabilidade. A cultura da empresa deve promover o **data literacy**, que é o letramento de dados, ensinando a todos a importância e os cuidados necessários ao trabalhar com dados.

## Mercado de Trabalho em Governança de Dados

**Cenário Atual**: Mercado em desenvolvimento, com variedade de títulos.

**Conhecimento Essencial**: Framework DAMA e teoria de governança de dados são fundamentais.

**Evolução da Carreira**: Tendência à especialização em disciplinas como arquitetura de dados, Master Data Management ou qualidade de dados.

**Valorização**: Conhecimento em governança de dados cada vez mais exigido em vagas de engenheiro e cientista de dados.

**Genéricos:**

- **Data Governance Officer** (Oficial de Governança de Dados)

        - **Perfil Analítico**
        - **Conhecimento do DMBoK**

        - **Conhecimento em modelagem de dados**

- **Profissionais de Privacidade de Dados**: Também uma função mais específica da área de governança de dados, focando em atividades que garantem e proteção da privacidade dos dados e que as atividades da organização estejam em conformidade com a lei geral de proteção de dados e quaisquer outras regulações específicas da área.

    - **As habilidades e qualificações mais importantes para esse tipo de profissional são**:

        - **Conhecimentos em privacidade de dados**

## Modelos de times de governança

**Centralizados**: Uma equipe de governança de dados responsável por todas as atividades de governança de dados em toda a organização.

São vantagens de um modelo de governança mais centralizado:

- **Simplicidade Organizacional**: Um único time centralizado facilita a coordenação e comunicação. Decisões podem ser tomadas de forma mais ágil.
- **Visão Holística**: O time central pode abordar todas as áreas da governança de dados. Garante consistência nas políticas e processos.
- **Conformidade Eficiente**: O time pode focar na conformidade com regulamentações como a LGPD; Implementação mais rápida de políticas e procedimentos.

São Desvantagens de um modelo de governança mais centralizado:

- **Sobrecarga de Responsabilidades**: O time pode ficar sobrecarregado com muitas tarefas; possibilidade de conflitos de prioridades.
- **Menos Especialização**: Falta de especialização em áreas específicas (qualidade, privacidade etc.); pode não atender a todas as necessidades detalhadas.

**Descentralizados**: Várias equipes de governança de dados responsáveis por diferentes áreas ou departamentos da organização.

São Vantagens de um modelo de governança mais descentralizado:

**Especialização Local**: As equipes locais podem se especializar em áreas específicas de dados e processos relevantes para suas necessidades. Isso traz melhor adaptação às nuances do contexto local e aos requisitos específicos do departamento.
**Maior Agilidade e Flexibilidade**: As decisões podem ser tomadas mais rapidamente, sem necessidade de esperar pela aprovação de uma equipe central.
**Engajamento e Autonomia**: As equipes locais têm maior autonomia, o que pode aumentar o engajamento e a responsabilidade em relação à governança de dados.
**Distribuição de Carga**: Reduz a sobrecarga de um único time central, permitindo que o conhecimento e as responsabilidades sejam distribuídos. Isso diminui o risco de gargalos em processos e aprovações.

São Desvantagens de um modelo de governança mais descentralizado:

**Inconsistência nas Políticas**: Risco de inconsistências e falta de alinhamento nas políticas e práticas de governança de dados entre diferentes equipes gerando, assim, dificuldade em manter uma visão holística e coerente dos dados da organização.
**Desafios na Conformidade**: Complexidade em garantir que todas as equipes sigam as mesmas diretrizes de conformidade, como a LGPD.
**Duplicação de Esforços**: Possibilidade de duplicação de esforços e recursos ao implementar soluções semelhantes em diferentes áreas. Pode levar a um uso ineficiente de recursos e tempo.

## Os 5 P's da Governança de Dados

Para entender o que uma pessoa profissional de governança de dados faz no dia a dia, é essencial conhecer os cinco P's:

1. **Princípios**
2. **Padrões**
3. **Processos**
4. **Procedimentos**
5. **Papéis**

### Princípios
---

Os princípios são grandes objetivos que norteiam as ações de governança de dados. Eles servem como guias para as decisões e práticas.

#### Princípio de Conhecimento dos Ativos

Este princípio foca em conhecer as bases de dados disponíveis na organização. Isso inclui:

- Saber quantas bases de dados existem (ex: 10 ou 1.000).
- Identificar se os ativos contêm dados sensíveis que exigem maior proteção.

#### Princípio do Acesso Mínimo

Um princípio crucial, que estabelece que, para um ativo de dado, deve-se sempre ter o menor nível de acesso possível.

**Exemplo**: Uma base de dados de RH com salários e informações sensíveis.

- Apenas pessoas do RH deveriam ter acesso.
- Dentro do RH, somente aquelas envolvidas em processos específicos (contratação, aumentos, pagamentos) teriam acesso.
- Isso mitiga riscos e aumenta a segurança.

#### Definindo Níveis Mais Altos de Acesso

- Em situações específicas, como a contratação de uma consultoria de RH para análise de diversidade, pode ser necessário conceder um nível mais alto de acesso a dados sensíveis.
- Isso não significa entregar todos os dados diretamente.
- A consultoria precisaria solicitar o acesso, e uma pessoa responsável (ex: gerente de RH) deveria autorizar formalmente (ex: por e-mail).
- Essa abordagem é vital para dados sensíveis, garantindo que o acesso seja controlado e justificado, mesmo quando se desvia do acesso mínimo padrão.

### Processos
---

Os processos são o segundo "P" dos cinco P's da Governança de Dados e representam a definição de etapas padronizadas para realizar ações relacionadas aos dados. Eles são fundamentais para implementar os princípios de governança.

**Exemplo de Processo: Ingestão de Novas Bases de Dados**

Para entender como os processos funcionam na prática, podemos considerar o exemplo de uma empresa de vestuário e o surgimento de uma nova base de dados. O processo de ingestão de bases garante que a criação de novos dados siga um fluxo estruturado.

#### Etapas do Processo de Ingestão de Bases

- **Criação do Modelo Lógico**: Define a estrutura conceitual da base de dados.
- **Criação do Modelo Relacional**: Detalha como os dados se relacionam entre si.
- **Criação e Aprovação do Dicionário de Dados**: Um documento que explica cada coluna da base de dados, submetido à governança para aprovação.
- **Definição de Regras de Qualidade**: Estabelece critérios para garantir a integridade e a precisão dos dados.
Somente após a conclusão dessas etapas, a base de dados pode ser criada.

**Importância dos Processos:**

- **Garantia da Qualidade dos Dados**: As etapas padronizadas asseguram que os dados sejam criados com um alto nível de qualidade.
- **Implementação de Princípios**: O processo de ingestão, por exemplo, implementa o princípio de conhecimento dos ativos, pois gera informações sobre os dados desde sua origem.
- **Continuidade e Padronização**: Permite que diferentes pessoas possam dar continuidade ao trabalho, mesmo que o responsável original não esteja disponível, devido à clareza e padronização das etapas.

### Procedimentos
---

Os procedimentos surgem para detalhar as macro etapas definidas pelos processos, garantindo que as atividades de governança de dados sejam executadas de forma específica e padronizada.

#### Onde os Procedimentos se Encaixam?

Os procedimentos são o nível mais específico dos processos. Enquanto os processos definem o que será feito em macro etapas, os procedimentos detalham como o processo irá funcionar, respondendo a perguntas como:

- **Quem é a pessoa responsável?**
- **Quais as ferramentas utilizadas?**
- **Quais são as dependências de cada um desses processos?**

Os procedimentos são, portanto, as maneiras mais específicas de realizar uma ação relacionada a dados, garantindo clareza e padronização na execução.

### Padrões
---

#### O que são Padrões?

Modelos arquétipos de consistência ou conformidade. Utilizados para melhorar a gestão e governança de dados nas organizações. Garantem consistência nas ações de dados.

#### Origem dos Padrões

Definidos externamente, não pela empresa. Podem vir de:

- Outros players de mercado (ex: ITIL, COBIT, ISO).
- O Estado, por meio de regulamentações (ex: LGPD).

#### Exemplo Prático: LGPD

A LGPD estabelece padrões para a coleta de dados pessoais. Exige finalidade específica para a coleta. Os dados só podem ser usados para a finalidade para a qual foram coletados.

**Exemplo**: Dados coletados para cadastro de cliente não podem ser usados para venda a outra empresa.

### Papéis
---

Papéis em governança de dados são conjuntos de responsabilidades atribuídas a uma pessoa ou área da organização, podendo ser temporárias ou permanentes. Eles garantem que haja clareza sobre quem é responsável por o quê em relação aos dados.

#### O Papel do Data Owner

- **Definição**: O Data Owner, ou pessoa dona dos dados, é um papel crucial com a responsabilidade de decidir quem pode e quem não pode ter acesso a dados específicos.

- **Importância**:
    - Centraliza a tomada de decisão sobre o acesso aos dados.
    - Garante que as decisões sejam tomadas por alguém com profundo conhecimento dos dados.
    - Fundamental para a privacidade e segurança de informações sensíveis.

- **Exemplo Prático**: Em uma base de dados de RH com informações sensíveis (endereço, salário, advertências), o Data Owner seria a pessoa que decide se uma consultoria externa de diversidade pode acessar esses dados e quais informações específicas seriam liberadas.

- **Aplicação**: É essencial que todas as bases de dados possuam um Data Owner.

#### Características Essenciais do Data Owner

- **Profissional de Negócio**: Deve ser alguém da área de negócio, não da área de tecnologia.
- **Conhecimento sobre os Dados**: Precisa entender o contexto e a relevância dos dados.
- **Nível de Autoridade**: Deve ter autoridade para tomar decisões importantes sobre o acesso e uso dos dados.

#### Atribuições Principais

- **Controle de Acesso**: Define quem pode e quem não pode acessar os dados.
- **Responsabilidade pela Qualidade**: Garante a qualidade dos dados e responde por auditorias relacionadas a eles.

#### Data Stewards

- **Definição**: Profissionais que conhecem os dados em profundidade e esclarecem dúvidas de outras pessoas na organização.

- **Analogia**: "Mordomo dos dados" – serve a organização com seu conhecimento detalhado sobre os dados.

#### Tipos de Data Stewards

##### Business Data Stewards (Data Stewards de Negócio)

- **Foco**: Conhecimento do contexto e significado dos dados para o negócio.

- **Exemplo**: Em uma base de dados de tecidos, se a coluna "tipo de venda" mostra 1, 2, 3 ou 4, o Business Data Steward explica que:
    - 1 = dinheiro
    - 2 = Pix
    - 3 = cartão de débito
    - 4 = cartão de crédito

- **Perfil**: Especialistas na área de negócio (ex: especialista em tecidos).

##### Technical Data Stewards (Data Stewards Técnicos)

- **Foco**: Conhecimento técnico sobre a estrutura e o formato dos dados.

- **Exemplo**: Em uma coluna "data da venda", se há dúvidas sobre o formato, o Technical Data Steward esclarece se é:
    - aa/mm/dd
    - dd/mm/aa

- **Perfil**: Profissionais de tecnologia (ex: administrador de banco de dados, engenheiro de dados).

- **Importância**:
    - Essenciais para esclarecer dúvidas sobre os dados, tanto de negócio quanto técnicas.
    - Garantem que os dados sejam compreendidos e utilizados corretamente por toda a organização.
