Stack SAM `datalake-alumart-dev` na região `us-east-2`.

s3://{bucket}/silver/{output_name}/year=YYYY/month=MM/

## Estrutura obrigatória do código

lambda_transform_gold/
├── lambda_function.py  # handler + SOURCES + BUILDERS + PARTITIONED + APPEND dicts
├── transforms.py       # build_dim_*, build_fact_* (zero imports AWS)
├── storage.py          # read_silver, save_gold (S3 helpers)
└── catalog.py          # ensure_glue_table, register_glue_partitions

## Princípios obrigatórios

1. **Parametrizado por evento:** cada invocação recebe `{"table": "nome"}` e processa exatamente uma tabela Gold - nunca tudo de uma vez.
2. **Carrega apenas o necessário:** `SOURCES` dict mapeia cada tabela Gold às fontes Silver que ela realmente precisa.
3. **Estratégia de carga:**
   - Dimensões + fact_sales: full replace (apaga e regrava)
   - fact_inventory: APPEND - nunca apaga partições anteriores
4. **Registro no Glue Catalog:** após salvar, registrar tabela e partições via Glue API (criar database `gold` se não existir).
5. **Sem alteração de lógica Silver:** a Gold apenas lê Silver, sem reprocessar ou corrigir dados - toda limpeza é responsabilidade da Silver.
6. **PyArrow schema explícito** nos arquivos Parquet (timestamp[us], double, int64, bool, string).
7. **Métricas obrigatórias no retorno do handler:**
   - table, rows_written, s3_key, partitions (lista), run_ts
